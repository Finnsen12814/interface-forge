# Source research playbook

Use live browsing when current examples or documentation matter. Verify availability, price, license, framework compatibility, and terms at the time of use.

| Need | Start with | Use it for | Guardrail |
|---|---|---|---|
| Broad web/app direction | https://godly.design/ | Curated sites, apps, heroes, CTAs, footers, icons | Extract patterns; never clone a featured site |
| Colors and typography | https://styles.refero.design/ | Real palettes, type pairings, design references | Validate contrast/licensing; do not impersonate brands |
| Editorial storytelling | https://www.deck.gallery/ | Composition, pacing, data-story pages | Membership/copyright boundaries apply |
| shadcn unusual components | https://skiper-ui.com/ | Focused interaction ideas | Separate free/premium; inspect license/dependencies |
| Animated React components | https://magicui.design/docs/components | Marketing accents and media effects | Use few effects; provide reduced-motion behavior |
| Animated components/blocks | https://smoothui.dev/docs/components and https://smoothui.dev/docs/blocks | Components, heroes, FAQs, pricing, stats | Adapt; do not ship the demo aesthetic unchanged |
| React/Tailwind alternatives | https://kokonutui.com/ and https://ui.unlumen.com/components | Compare implementation approaches | Verify accessibility, license, maintenance, bundle cost |
| Illustration | https://undraw.co/illustrations | Brand-adjustable SVG illustration | Read https://undraw.co/license before use |
| Charts and diagrams | https://bklit.com/ | Data-visualization composition | Choose by analytical task; never distort data |
| Web animation | https://motion.dev/ | Production JS/React/Vue motion | Prefer transform/opacity and reduced motion |
| Spring interaction | https://www.react-spring.dev/ | Gesture-led React animation | Use when physics improves manipulation |
| Motion patterns | https://motion-primitives.com/ | Animated primitive references | May block automation; never fabricate inspection |
| Transition examples | https://transitions.dev/library.html | Buttons, words, dropdown studies | Do not animate every control |
| Interactive 3D | https://spline.design/ | Product demos and intentional 3D | Budget loading, GPU, fallback, and accessibility |

## Sequence

1. State 1–3 questions, such as “How should a dense desktop sidebar collapse?”
2. Select at most 2–4 relevant sources; prefer primary docs for implementation.
3. Capture `pattern → reason → adaptation → risk`, not adjectives.
4. Compare two approaches for high-impact surfaces.
5. Decide what not to import.
6. Confirm license and provenance before copying code or assets.

Evidence note: problem; URL/date; observed pattern; fit; adaptation; accessibility/performance/license risk; decision. Separate observation from inference. If inaccessible, note it and use another source.
